# Segment 2255 — engine library: VGA graphics, heap, math, 3D object renderer

Segment `2255:0000`–`2255:B686` (46.7 KB, 252 Ghidra functions plus ~22 entry
points Ghidra did not create, listed in `tools/re/symbols/seg_2255.tsv` with
the note "(not in Ghidra function list)").

This is **not** one C module. It is the author's (Andre Gagnon) reusable
low-level library, mostly hand-written assembly with a few C files, linked
into one code segment:

Note: the "strings:" hints that `re/export/summary.txt` lists for this
segment (joystick calibration, "Search aborted", "Team split", …) are false
positives: they come from immediates such as the code segment value 0x2255
pushed for near calls or table offsets that happen to fall inside string
literals. The only strings this segment uses are the `.pnt` suffix and the
error messages "Couldn't init coherence" (DS:07C3) and "can't SaveClipBox
recursively." (DS:4FD9).

The game only ever runs the library in **mode 6** (VGA 320x200, 256 colours,
unchained "Mode X", two pages). Most per-mode jump tables contain an entry
only for mode 6; code for modes 0–5 (CGA/EGA/planar) exists but is dead in
the game and is described only briefly.

Initialisation order (1959:007B / 1959:0265): `gfx_save_video_mode` (0D7E),
`gfx_init(6)` (04DE), later `sys_cpu_detect` (6699), `sys_div0_install`
(6C26), `r3d_set_default_aspect` (3E73), `mdl_swap_buffer_set(0xD78A,0x10)`
(4CE5), `xf_set_vertex_buffer(0xCF8A,0x80)` (42B6), `mdl_load_all` (0177).
Per mission: `world_begin` (01E7) → many `world_add_object` (0234) →
`world_end` (02B0); per frame `r3d_render_view` (3090); at the end
`world_free` (01CF). Shutdown: `sys_div0_remove` (6C5C),
`gfx_restore_video_mode` (0D92).

## 1. Conventions used in this document

* **Calling conventions.** Functions ending in `RETF n` are Microsoft
  `far pascal`: arguments are pushed left to right, so the *first source
  argument is at the highest stack offset*. Ghidra's `param_1` is at `[bp+6]`,
  i.e. the **last** source argument. All argument lists below are in source
  order. Functions ending in plain `RETF`/`RET` are cdecl (Ghidra order =
  source order). Many assembly routines take registers (noted as `AX=`…).
  Long (32-bit) arguments occupy two words (low word at the lower address).
* **Angles**: unsigned 0..2879 (`0xB40` = 360°, 1 unit = 1/8°). 90° = 720
  (0x2D0), 180° = 1440 (0x5A0), 270° = 2160 (0x870).
* **Fixed point**: *1.14* = signed 16-bit, 0x4000 = 1.0 (sin/cos, matrices,
  frustum normals). *16.16* = signed 32-bit. *2.14 slope* = 16-bit, 0x4000 = 1.
* **World units**: object/camera positions are signed 32-bit *world units*.
  The game code passes positions in *game units* and the library stores
  `game << 8` (1 game unit = 256 world units). Grid cells are 2^24 world units
  (65536 game units).
* **3D axes** (camera space): x right, y up, z forward. Screen
  `sx = cx + x*2^zoom/z`, `sy = cy - y*2^zoom/z`. World: y up; heading 0 looks
  along +z, heading 720 (90°) along −x (counter-clockwise seen from above);
  positive pitch tilts the view up.
* "Mode X byte" = 4 horizontally adjacent pixels at the same offset in the 4
  planes; plane p holds pixels with `x % 4 == p`.

## 3. VGA graphics driver (mode 6)

### 3.1 Video mode and memory layout

`gfx_init` (04DE, `AX` = mode) calls `gfx_bios_set_mode` (0CA6), which sets
bits 4–5 of the BIOS equipment byte (0040:0010) to `20h` (or `30h` if bit 0 of
`g_mode_flag_tbl[mode]` is set), then for mode 6: INT 10h mode 13h, sequencer
memory mode: clear chain-4 (bit 3) and set bit 2; graphics mode register:
clear bit 4; graphics misc: clear bit 1; map mask 0Fh; clear all 256 KB; CRTC
underline register (14h) bit 6 cleared, mode control (17h) bit 6 set (byte
addressing). Other library modes (unused by the game): 0 → INT 10h 04h,
1 → 0Dh, 2 → 0Eh, 3 → 10h, 4 → 13h (linear), 5 → 09h.

State after `gfx_init(6)`:

* `g_gfx_mode`=6, `g_gfx_mode_flags` = `g_mode_flag_tbl[6]` = 2 (bit 1 lets
  the 4A1C frame limiter run).
* 320 x 200, 80 bytes per row, `g_row_offsets[y] = 80*y`, page size 16000.
* Two pages: page 0 = `A000:0000`, page 1 = `A400:0000` (VRAM byte offset
  0x4000). Pixel (x,y) of a page is byte `80*y + x/4` of plane `x&3`.
* Off-screen VRAM `A800:0000`–`AFFF:000F` (0x7FF paragraphs) becomes the VGA
  heap (`heap_vga_init`, 4E16:023B) used for all bitmaps in mode 6.
* Surface descriptors: `g_screen` (F400) = current draw page, F40A = page 0,
  F414 = page 1 (see 3.7).
* 32 dither patterns initialised, vertical-retrace polarity measured
  (`gfx_vsync_detect`), draw page 0, display page 0, clip = full screen, both
  row caches = 0xFF. `gfx_pages_init` (060D, called at startup) then draws on
  page 1 while page 0 is shown.

Paging: `gfx_set_draw_page(AX)` sets `g_draw_page` and `g_draw_seg`
(A000/A400) and the segment in `g_screen`; `gfx_set_display_page(AX)` sets
`g_display_page` and writes the CRTC start address `page_seg << 4` (0 or
0x4000) with `gfx_set_crtc_start` (0840: reg 0Dh = low byte, 0Ch = high).
`gfx_flip` (0649, AL = flip, DL = wait): if AL≠0 in mode 6 — draw page :=
current display page, display page := 1 − old display page, exchange the two
200-byte row caches; if DL≠0 also reset the 256 Hz frame tick counter and
busy-wait 5 ticks (4A1C:01A8/0192), so the new start address has been latched
before the old page is overwritten. `gfx_copy_page` (AD4B, AX = source page,
DX = destination page) resets the clip to full screen and copies the whole
16000-byte page (latched copy). `gfx_clear` (0735, AL = colour) fills every
row of the draw page via `gfx_fill_rows` with a temporary full-screen clip.

Vertical retrace: `gfx_vsync_detect` counts status-port (3DAh) polls while
bit 3 is set and while it is clear; `g_vretrace_level` = 8 if the clear phase
was longer (normal), else 0. `gfx_wait_vretrace` (0FAE) waits until
`(in(3DAh) & 8) == g_vretrace_level`. (0F8E additionally waits for the end of
retrace.) These routines run with interrupts disabled and restore flags with a
`push cs / call iret-stub` idiom (0F7B, 0F88, 0FBE are single `IRET`s).

Row cache (`g_row_color` F0AA, 200 bytes for the draw page; F172 for the other
page): entry = colour a whole row was last filled with by `gfx_fill_rows_x`,
0xFF = unknown. Every other primitive stores 0xFF for each row it touches.
`gfx_fill_rows_x` skips rows whose entry already equals the fill colour. A port
may simply always fill; the cache only changes results if something wrote the
page without going through the library.

### 3.2 Clip rectangle

`gfx_set_clip(x, y, w, h)` (0FD0): `x0=x, y0=y, w, h, x1=x+w-1, y1=y+h-1,
cx=(x0+x1)>>1, cy=(y0+y1)>>1` (unsigned shift), then mode 6: `wbytes=w>>2,
wwords=w>>3, xb0=x0>>2, xb1=x1>>2`. All primitives clip against
`[x0,x1] x [y0,y1]` inclusive. `cx,cy` is also the 3D projection centre.
`gfx_clip_full` = `gfx_set_clip(0,0,320,200)`. 07F7/0825 save and restore one
level (error text "can't SaveClipBox recursively.").

### 3.3 Colours and dither patterns

Every drawing call takes a 16-bit *colour word*: low byte = palette index,
high byte = dither pattern id (0xFF = solid). `gfx_begin_color` (18C5, AX =
colour word) stores the index in `g_cur_color`, selects the pattern if it
changed (`gfx_set_pattern`, 2422) and chooses the span routine
`g_span_fn = g_span_tbl[mode + 7*patterned]` (mode 6: 2129 solid, 21C5
dithered); it also patches the call inside the polygon span loop.

Mode-6 pattern semantics (pattern id p used as a 4x2 transparency mask):

* spans, rectangles, polygons and lines: on **even** rows the low nibble
  `p & 0xF` is used, on **odd** rows the high nibble `p >> 4`;
* a pixel is written only if bit `3 - (x & 3)` of that nibble is set (bit 3 =
  leftmost pixel of each group of 4); other pixels are left unchanged;
* quirk: the single-pixel routine (2023, used by `gfx_pixel` and point
  primitives) swaps the rows: even rows use the high nibble, odd rows the low
  nibble.

(Implementation: `g_pattern_masks[0]` = `rev4(p & 0xF) * 0x11`,
`[1]` = `rev4(p >> 4) * 0x11`, used as VGA map masks; `g_bitrev4` at 5076.)
`gfx_init_patterns` builds CGA/EGA forms of the 32 templates at DS:5324 for
pattern ids 0x10..0x2F; in mode 6 it does nothing useful.

### 3.4 Filled primitives

**Span** (`gfx_hspan` 205A, pascal `x0, x1, y`, current colour; mode-6
routines 2129/21C5 with AX=x0, DX=x1, BP=y): ignored unless `y0<=y<=y1`
(clip); `x0 = max(x0, clip_x0)`, ignored if `x0 > clip_x1` or
`x1 < clip_x0`, `x1 = min(x1, clip_x1)`; row marked 0xFF; pixels `x0..x1`
inclusive are set (with the pattern mask). The caller must ensure x0 <= x1.

**Horizontal / vertical line, rectangle**: `gfx_hline(x0,x1,y,c)` =
begin_color + span. `gfx_vline(x,y0,y1,c)` = `gfx_line(x,y0,x,y1,c)`.
`gfx_rect(x,y,w,h,c)` (0786) draws, in this order: top `hline(x, x+w-1, y)`,
right `vline(x+w-1, y, y+h-1)`, bottom `hline(x, x+w-1, y+h-1)`, left
`vline(x, y, y+h-1)`.

**Filled rectangle** `gfx_fill_rect(x,y,w,h,c)` (25CE): nothing if h <= 0;
spans `x..x+w-1` on rows `y..y+h-1` that lie inside `[clip_y0, clip_y1]`.

**Row fill** `gfx_fill_rows(y, n, c)` (0AE6 → 0AF0, solid colour only): rows
`y..y+n-1` clipped to the clip box; each row is filled from byte column
`xb0` for `2*wwords` bytes, i.e. pixels `(x0 & ~3) .. (x0 & ~3) + 8*(w>>3) - 1`
(the clip width rounded *down* to 8 pixels), skipping rows whose row cache
already holds the colour.

**Split rows** `gfx_fill_split_rows(xs*, y0, y1, L, R, unused)` (0B74), used
for the horizon: for row `y = y0..y1`, `x = xs[y-y0]`:
`x < clip_x0` → whole row filled with R (via fill_rows); `x >= clip_x1` →
whole row L; otherwise pixels from byte column `xb0` up to and including `x`
get L and pixels `x+1 .. 4*xb1+3` get R (byte granular on both ends of the
clip box).

**Filled circle** `gfx_fill_circle(x, y, r, c)` (099A): r < 0 or r >= 750 →
nothing; r = 0 → `gfx_pixel`; r = 1 → spans `(x,x,y-1)`, `(x-1,x+1,y)`,
`(x,x,y+1)`. Otherwise reject if the circle's bounding box is outside the clip;
rows `max(y-r,clip_y0) .. min(y+r,clip_y1)`; midpoint loop with a table of
left x per row:

```
d = 3 - 2r; i = 0; j = r
while i < j:
    octants(i, j); if d < 0: d += 4*i + 5 else: d += 4*(i-j) + 10; j -= 1
    i += 1
if i == j: octants(i, j)
octants(a,b): left[y+b] = left[y-b] = x - a; left[y+a] = left[y-a] = x - b
              (only rows inside the clip are stored)
for each visible row: span(left[row], 2*x - left[row], row)
```

**Polygon** `gfx_fill_polygon(pts*, n, c)` (10FC, cdecl; `pts` = n pairs of
s16 x,y, any winding). Assumes the polygon is y-monotone (convex in
practice). Algorithm (self-modifying code; behaviour reproduced here):

1. Find `ymin`/`ymax`; the top vertex is the *last* index with `y==ymin`. If
   `ymax <= clip_y0` nothing is drawn.
2. If several vertices share `ymin` (flat top): among them take the leftmost
   (smallest x) as the left start and the rightmost as the right start. If
   *all* vertices share one y, draw the single span `[min x, max x]` on that
   row (if `ymin <= clip_y1`) and stop. Otherwise each chain walks away from
   its start vertex skipping further vertices on the same row.
3. With a single top vertex the left chain continues to the neighbour
   (index−1 or index+1, cyclic) with the smaller x, the right chain to the
   other one (equal x: index−1 is left).
4. If `ymin < clip_y0`, both chains are advanced to row `clip_y0`; an edge
   crossing it is cut by repeated halving of (dx,dy) (140E).
5. Edge set-up for an edge from (x,y) to (x',y'), `dx = x'-x`, `dy = y'-y`
   (horizontal edges are skipped): if `|dy| <= |dx|` use `dy' = dy+1`, else
   `dy' = dy`; `q = dx / dy'`, `r = dx % dy'` (truncated). For dx >= 0:
   `err = 2r - dy`, per row `x += q+1, err += 2r - 2dy` if `err >= 0`, else
   `x += q, err += 2r`. For dx < 0 (r' = |r|): `err = 2r' - dy - 1`, per row
   `x += q-1, err += 2r' - 2dy` if `err >= 0`, else `x += q, err += 2r'`.
   Pre-step: a *left* edge with `q <= -1` and a *right* edge with `q >= 1`
   immediately apply one row step at set-up (so x-major edges start at their
   extreme x).
6. For each row from the top (clipped) down to `min(ymax, clip_y1)`: if
   `xl > xr` swap the complete left/right chain state; span
   `[min(xl, prev_r), max(xr, prev_l)]` where prev_l/prev_r are the span ends
   of the previous row (initially −32768/+32767) — this joins rows of thin
   slanted polygons; then remember the span; step both edges; `y += 1`; when y
   reaches the lower vertex of an edge the chain switches to the next edge,
   with x reset to that vertex's x. When a chain has no further vertex below,
   one last span is drawn on that row and the routine ends.

**Pixel** `gfx_pixel(x, y, c)` (1F9E): inside-clip test, row marked,
pattern test (see quirk above).

### 3.5 Lines

`gfx_line(x0, y0, x1, y1, c)` (1962). A line is *x-major* if
`|y0-y1| < |x0-x1|`, otherwise *y-major* (a single point is y-major).
Differences that overflow 16 bits are computed from halved coordinates.

x-major:
```
if x0 >= x1: swap endpoints
reject if x0 > clip_x1 or x1 < clip_x0
dx = x1-x0; dy = y1-y0; if dy != 0: dy += sign(dy)          # extended minor delta
if |dx| > 0x3FFF: dx >>= 1, dy >>= 1  elif |dy| > 0x3FFF: dx >>= 1, dy >>= 1
s = ((dy << 15) + dx) / (2*dx)          # 32/16 signed, truncating; 2.14 slope
frac = (y0 & 2) << 14 ; if s < 0: frac |= 0x3FFF
clip x: x0 < clip_x0: y0 += ((clip_x0-x0)*s) >> 14, x0 = clip_x0, restart
        x1 > clip_x1: y1 += ((clip_x1-x1)*s) >> 14, x1 = clip_x1, restart
clip y (s >= 0): reject if y0 > clip_y1 or y1 < clip_y0
        y0 < clip_y0: x0 += (((clip_y0-y0) << 16) / s) >> 2, y0 = clip_y0, restart
        y1 > clip_y1: x1 += (((clip_y1-y1) << 16) / s) >> 2, y1 = clip_y1, restart
     (s < 0): the same with the roles of y0/y1 and clip_y0/clip_y1 mirrored
"restart" re-evaluates everything (major axis, deltas, slope) from the new endpoints.
draw: acc = frac; top = acc & 0xC000; n = x1 - x0; x = x0; y = y0
  plot(x,y)
  repeat n times:
      x += 1; acc += s (16-bit wrap)
      if (acc & 0xC000) != top: top = acc & 0xC000; if this is not the last pixel: y += sign(s)
      plot(x,y)
```
(`>> 14` above means: take bits 14..29 of the 32-bit product, arithmetic.)

y-major (no ±1 extension, round-to-nearest start):
```
if y0 >= y1: swap; reject if y0 > clip_y1 or y1 < clip_y0
dx = x1-x0; dy = y1-y0; same 0x3FFF halving; s = ((dx << 15) + dy) / (2*dy)
clip y first (x0/x1 += Δy*s >> 14), then x (y += (Δx<<16)/s >> 2), restarting
acc = (x0 << 14) + 0x1FFF (16-bit); top = acc & 0xC000
for each row y0..y1: if (acc & 0xC000) != top: top = ...; x += sign(s)
                     plot(x,y); acc += s
```
Pixels honour the dither pattern (lines use the span convention: even row →
low nibble).

### 3.6 Scaled RLE sprites

`gfx_sprite_scaled(x, y, w, h, spr far*)` (B0D6, cdecl) draws a run-length
encoded sprite scaled to `w x h` pixels with its top-left at (x,y).
`gfx_sprite_centered(spr, cx, cy, w, h)` (28FA, pascal) calls it with
`x = cx - w/2`, `y = cy - h/2` (C division) when `|cx|,|cy| < 10000`, setting
DS:F6D4 = 1 during the call. Used by many modules (soldiers, billboards).

Sprite format (same as the `.RLE` resources):

| Offset | Size | Meaning |
|---|---|---|
| 0 | u16 | source width `sw` |
| 2 | u16 | source height `sh` |
| 4 | u16 | transparent colour (low byte) |
| 6 | u16 | unused by mode 6 |
| 8 | … | `sh` rows: u16 `len` = number of data bytes that follow, then the row data |

Row data: control byte `c`; if `c & 0x80` a run of `c & 0x7F` pixels of the
colour in the next byte, else `c` literal colour bytes follow. Pixels equal to
the transparent colour are not drawn. If DS:D79A (`g_blit_remap_on`) is
non-zero every colour is translated through the 256-byte table at the far
pointer DS:00E6 before the transparency test.

Scaling (nearest neighbour, Bresenham style, identical on both axes):

```
reject if w <= 0 or h <= 0
clip: skip_rows = max(0, clip_y0 - y), skip_cols = max(0, clip_x0 - x),
      vis_h / vis_w = parts inside the clip box; nothing if either <= 0
mark rows (y+skip_rows) .. +vis_h-1 dirty
src = first row; acc = sh >> 1
n = skip_rows
while n > 0:                                # exact original order (see note)
    src = next_row(src); acc += h
    while acc >= sh and n > 0: acc -= sh; n -= 1
rows_left = vis_h
acc += h ; while acc < sh: { src = next_row(src); acc += h }
loop:
    draw_row(src)
    acc -= sh ; rows_left -= 1 ; if rows_left == 0: done
    while acc < sh: { src = next_row(src); acc += h }
draw_row: ax = sw >> 1; col = 0
    for each source pixel p (decoded from the runs):
        ax += w
        while ax >= sw:
            ax -= sw
            if col < skip_cols: col += 1 ; continue        # clipped left columns
            if p != transparent: put(x + col, current row, p)
            col += 1 ; if col == skip_cols + vis_w: return
```
Note: when rows are clipped at the top, the skip loop advances the source
row *before* accumulating, so an upscaled sprite (h > sh) clipped at the top
starts one source row too late (original behaviour).

### 3.7 Bitmaps (surfaces)

Descriptor (10 bytes): `+0 u8 flags` (bit 0 = screen/planar layout),
`+2 u16 width`, `+4 u16 height`, `+6 u16 bytes_per_row`, `+8 u16 segment`
(data at `seg:0000`). In mode 6 every bitmap uses the page layout (pixel
(x,y) = plane x&3, byte `y*bpr + x/4`) and lives in off-screen VRAM.

* `bmp_create` (2867; AX=w, DX=h, BX=desc): flags 0, `bpr = ((w+7)>>3)*2`,
  memory from the VGA heap (mode 6) or far heap; returns success.
  `bmp_free` (28CA), `bmp_desc_clear` (2859, zero 10 bytes).
* `bmp_blit(src, sx, sy, dst, dx, dy, w, h)` (A7E9): if `dst.seg ==
  g_draw_seg` mark rows `dy..dy+h-1` dirty; mode 6: latched copy of `w>>2`
  bytes (all planes) per row for h rows, starting at byte columns `sx>>2` and
  `dx>>2` (x and w are effectively multiples of 4).
* `bmp_blit_masked(src, sx, sy, dst, dx, dy, w, h, mask_seg)` (AA26): as
  above but for each pair of source bytes (8 pixels) at source offset `o`, the
  mask byte `mask_seg:(o>>1)` supplies the plane mask: high nibble for the
  first byte, low nibble for the second (bit p = pixel `x%4 == p`); only
  masked pixels are copied; `w>>3` pairs per row.
* `gfx_vram_copy(sseg, soff, dseg, doff, n)` (0856): latched byte copy.

## 4. Heap manager (2982–2DF3)

Generic paragraph heap used through the wrappers in segment 4E16 (near heap
DS:5476, far heap DS:5482 over one big DOS block, VGA heap DS:548E over
A800–AFFF). A port does not need it; the layout is given for completeness.

Heap descriptor (12 bytes): `+0 base seg`, `+2 anchor seg` (= base),
`+4 rover seg`, `+6 last paragraph seg`, `+8 u8 flags` (bit 1 allocate from
the top of a free block, bit 2 fill freed blocks with 0xAA; for the VGA heap
also "VGA memory"), `+9 u8 initialised`, `+0A owner tag`.

Block header (first paragraph of every block, `seg:0000`):
`+0 type` (0x0F free, 0x0B used; the anchor has type 0 and size 1, the last
paragraph of the heap is marked 0x0B), `+2 size` in paragraphs including the
header, `+4 next`, `+6 prev` (circular free list through the anchor; used
blocks have 0/0), `+8 owner tag`, `+0A 0xABCD`, `+0C 0xEAEA`, `+0E 0x1298`
(guards of a used block). The data segment returned to callers is header+1.

* `heap_init(heap, seg, paras, flags)`: anchor at seg, one free block of
  `paras-2` at seg+1, end marker at seg+paras-1. Fatal (4EAC:0026, code 0x66)
  if already initialised, seg==0 or paras<3.
* `heap_alloc(heap, n)`: `need = ((n+15)>>4)+1`; first fit on the free list
  starting at the rover (wrapping once through the anchor); rover := found
  block's next. If `size-need < 8` the whole block is taken, else it is split:
  normally the low part is returned and the rest stays free; with flag bit 1
  the high part is returned. Returns 0 if nothing fits.
* `heap_free(heap, seg)`: validates range and guards (fatal otherwise),
  inserts the block after the anchor, optionally fills it with 0xAA, merges
  with the physically following free blocks and with the physically preceding
  free block (found by walking from the anchor), rover := result.
* `heap_realloc(heap, seg, n)`: shrink in place (split if the remainder is at
  least 8 paragraphs or the next block is free) or grow into a following free
  block; fatal on a bad block.
* `heap_free_owner`, `heap_set_owner`, `heap_set_flags` as named.

## 5. Math library

### 5.1 Trigonometry

* `math_sin(AX)` (613F): `a<720 → T[a]`, `a<1440 → T[1440-a]`,
  `a<2160 → -T[a-1440]`, else `-T[2880-a]`, where `T` = 721 s16 values at
  far `5327:000A` (sin 0°..90° in steps of 1/8°, max 16383; not an exact
  closed formula — load it from the executable). Input must be 0..2879.
* `math_cos(AX)` (618C) = `math_sin((a+720) mod 2880)`.
* `math_sin_fx` / `math_cos_fx` (61E7/61F6): the same value times 4 as a
  32-bit 16.16 number (DX:AX).
* `math_angle_wrap(AX)` (6205), `math_angle_add` (621E: `[BX] = wrap([BX]+AX)`).
* `math_atan2(AX=a, DX=b)` (4481) with table `A` = 513 s16 values at far
  `52E7:0008` (floor(8·atan(r/512) in degrees), 0..360):
  ```
  q = (a<0) | 2*(b<0); a=|a|; b=|b|
  if b < a: t = A[(b<<9)/a]            (32/16 unsigned division)
  else:     t = 720 - A[b==0 ? 0 : (a<<9)/b]
  q==0: t; q==1: 1440-t; q==3: 1440+t; q==2: 2879-t
  ```
  (0 along +a, 720 along +b; note 2879 rather than 2880 in the 4th quadrant.)
* `math_heading(x0,z0,x1,z1)` (63D7, pascal, 32-bit coordinates):
  `dx = x1-x0`, `dz = z1-z0`; while either high word is not a pure sign
  extension, shift both right by 8; then both `>>= 2`;
  `h = atan2(a=dx, b=dz) - 720` (+2880 if negative). Heading 0 = +z,
  720 = −x.
* `math_pitch(ax,ay,az,bx,by,bz)` (64FD, pascal): deltas B−A, same byte
  normalisation, `>>2`; `d = int(sqrt(dx²+dz²))`; returns `atan2(d, dy)`
  (0..720 up, 2880−θ down; callers use `>>3` for degrees).
  `math_heading_pitch` (643F) returns both; only reached from the unused 4275.
* `math_rotate_2d(pt, centre, a)` (62D0, pascal): with `s=sin a, c=cos a`
  (1.14), `dx,dy` = pt − centre and `R(v) = (v + 0x2000) >> 14` (32-bit
  arithmetic, i.e. `v/16384` rounded half up):
  `x' = cx + R(dx*c) - R(dy*s)`, `y' = cy + R(dx*s) + R(dy*c)`.

### 5.2 Fixed point and vectors

* `math_sqrt_long(v)` (6368): `n=0; while v >= 4<<16: v >>= 2, n++`;
  `v <<= 12`; integer square root `r` (16-bit, bit by bit from 0x8000);
  result (16.16) = `(r << 16) >> (6-n)` (or `<<` if n>6).
* `math_fmul(a,b)` (65B9): signed 16.16 product computed on magnitudes,
  `(|a|*|b|) >> 16` without the low×low low word, sign applied last.
* `math_fdiv(a,b)` (661B): `a/b` in 16.16; the divisor is first shifted right
  (with the dividend) until it fits 16 bits; quotient = integer part then
  fraction `(rem<<16)/b`; no overflow protection.
* Matrices are 9 s16 in 1.14, row major; `M×v` means
  `out_i = sum_j M[i][j]*v_j`.
  `math_mat_mul(b, a)` (9704): `b := a × b`, every element
  `(sum of 3 products) >> 14` truncated to 16 bits.
  `math_mat_vec_near` (98A7, AX = vector of 3 longs of which only the high
  words are read, BX = matrix): `out = M × v`; each result stored as a long
  with high word `sum >> 14` and low word `(sum << 2) & 0xFFFF`.
* `math_rot_matrix(out, a0, a1, a2)` (3726): with `ci=cos ai, si=sin ai`
  (1.14):
  ```
  M  = [[c2, s2, 0], [-s2, c2, 0], [0, 0, 0x4000]]
  M := [[0x4000,0,0], [0, c1, s1], [0, -s1, c1]] × M
  M := [[c0, 0, -s0], [0, 0x4000, 0], [s0, 0, c0]] × M
  ```
  (a0 = object +0x12 "heading", a1 = +0x14, a2 = +0x16.)

### 5.3 Random numbers

Additive lagged Fibonacci generator (x[n] = x[n-32] + x[n-17] mod 2^16),
used by the whole game (78D6 has ~110 call sites):

```
state[32] (DS:55D8) is initialised in the data segment to a copy of the
32 words at far 5382:0000 (load them from st.exe; the first is 0x3D52),
i = 0 (DS:5618), j = 15 (DS:561A)
rng_next():  state[i] += state[j]; r = state[i]; i = (i+1)&31; j = (j+1)&31; return r
rng_range(n) (AX = n > 0): return (rng_next() & 0x7FFF) % n
```
`rng_seed(s)` (7854) would reset the state to table+s and
`i = (s & 0xF80) >> 7, j = (i+15) & 31`, but it is never called: the
sequence always starts from the values above.

### 5.4 CPU detection and divide overflow

`sys_cpu_detect(&speed, &frac)` (6699) counts loop iterations during 6 BIOS
ticks (`speed = count / 6519`, `frac = (rem*2)/6519`) and returns 86, 186
(0xBA), 286 (0x11E) or 386 (0x182) from the classic FLAGS/shift tests; the
result is stored in `g_cpu_type` (F482).

`sys_div0_install` (6C26) hooks INT 0. The handler (6B74) sets
`g_div_overflow` (55B4) = 0xFF; on a 186 or later it advances the saved IP
past the faulting `DIV/IDIV` (decoding the ModRM byte); if the fault happened
inside the generated projection code it applies the fix-ups of §9.1. Many
routines test `g_div_overflow` after a division and retry with a halved
dividend. A port must reproduce these results explicitly.

## 6. 3D model data

### 6.1 Model table and descriptors

The game's model list is a far table at `514B:0000` (97 entries of 6 bytes,
terminated by a zero descriptor): `+0 u16 descriptor (DS offset)`,
`+2 u16`, `+4 u16` (category/flags used by other modules, not by 2255).
All descriptors, LOD models, primitive records and BSP trees live in DGROUP
(initialised data of the executable); the `.pnt` files supply only vertex
coordinates, vertex parents and colours.

Model descriptor (DS):

| Off | Type | Meaning |
|---|---|---|
| +00 | u8 | draw layer: < 0x80 flat layers drawn in ascending order without depth sort; >= 0x80 depth sorted (0x80 for normal objects). Values used: 02 flat ground, 03 pad, 04 shadows, 09 sea/bay, 0A rivers, 0C dock, 10 ripples/arc, 80 |
| +02 | s16 | bounding radius in model units |
| +04 | s16 | horizontal radius, aspect corrected (computed, §8.1) |
| +06 | s16 | vertical radius, aspect corrected (computed) |
| +08 | s32 | bounding radius in world units (= radius << (8+s)) |

| +0E | u16[3] | LOD distance thresholds t0,t1,t2 (units of 65536 world units; 0 = unused) |
| +14 | u16[3] | LOD model pointers (see 8.3 for the index rule); every game model has only +14 |

LOD model (DS):

| Off | Type | Meaning |
|---|---|---|
| +00 | u8 | number of primitive records |

| +02 | far ptr | pre-draw hook (segment 0 = none), called with DS:F61C = object being drawn |
| +06 | far ptr | generated transform code (filled by `mdl_compile`) |
| +0A | u16 / far ptr | BSP root; if flag bit 0: far pointer of a custom draw routine |
| +0C | u8 | number of leading type-0 records (their facing caches are reset per object) |
| +0D | u8 | flags: bit 0 custom draw routine, bit 1 compiled vertex code (set on all 97 models), bit 2 coordinates use only 7 bits (table transform) |
| +0E | … | primitive records, then BSP nodes |

Primitive record (all pointers are DS offsets):

| Off | type 0 polygon | type 1 line | type 2 point | type 3 disc | type 4 callback |
|---|---|---|---|---|---|
| +00 | type byte | | | | |
| +01 | u16 facing record | same | same | same | same |
| +03 | colour word | colour word | colour word | colour word | far ptr routine |
| +05 | u8 facing cache | u8 v0 | u8 v | s16 radius | |
| +06 | u8 n | u8 v1 | | | |
| +07 | u8 v[n] | | | u8 v | u8 v |
| size | 7+n | 7 | 6 | 8 | 8 |

Type byte: bits 0–2 primitive type; bits 3–4 visibility: `00` always drawn,
`08` never drawn, `10` drawn when the facing test of its facing record gives
0x10, `18` drawn when it gives 0x18 (test in 8.6: 0x10 if `n·P1 >= 0`). The
facing record is a type-0 record (usually the primitive itself); several
coplanar primitives may share one. Its byte +05 caches the facing result per
drawn object (0 = not yet computed); the first three vertex indices
(+07..+09) of the facing record define its plane.

BSP node:

* internal node (bit 0 = 0): `+00` type byte (bits 3–4 as above), `+01`
  facing record, `+03` child A, `+05` child B. If the node is "visible" (its
  facing test succeeds) child B is drawn first and child A last, otherwise A
  first then B.
* leaf (bit 0 = 1): if bit 1: `+01 u8 count`, `+02 u16[count]` primitive
  pointers drawn in order (each subject to its own visibility test). If
  bit 2 the leaf is an *articulated part*: after the list follows
  `+00 s16 a0, +02 s16 a1, +04 s16 a2` (part rotation angles, modified at run
  time by the model hooks), `+06` (unused), `+07 u8 first vertex`,
  `+08 u8 last vertex` of the part.

### 6.2 PNT file format (`point.lib`, verified on all 121 files)

Little-endian, 0x1C-byte header followed by data referenced by offsets from
the start of the file. Up to three LOD sets:

| Off | Type | Meaning |
|---|---|---|
| 00 | u8[3] | per-LOD flags: bit 3 = compile with 32-bit precision (large models: jungle, sea, bay, riverl, riverh, road, trail, spheres, runway LOD1) |
| 03 | u8 | 0 |
| 04 | u16[3] | offset of the vertex array of LOD 0..2 (0 = none) |
| 0A | u16[3] | offset of the parent index array |
| 10 | u16[3] | offset of the colour array (0 = none) |
| 16 | u8[6] | 0 |
| 1C | … | data |

For LOD i with model M (`nv` = M+01, `np` = M+00): vertex array =
`nv` × (s16 x, s16 y, s16 z) in model units; parent array = `nv` bytes, each
`0xFF` (relative to the object centre) or the index of an earlier vertex (the
vertex is stored relative to it for the code generator); colour array = `np`
bytes, one per primitive record in record order (type-4 records consume a
byte but have no colour). All 97 referenced files have exactly
`0x1C + 7*nv (+ np)` bytes with the arrays packed in this order; 24 files are
not referenced by the model table (B52, BLACK, C47, HANGAR, RUNWAY, …;
HANGAR and RUNWAY contain two LOD sets).

### 6.3 Loading (mdl_load_all / mdl_load_pnt)

For every table entry: `mdl_swap_in` (no effect in the game), then
`mdl_load_pnt(desc)`: build `name + ".pnt"`, load it from the libraries into
the far heap (allocating from the top), fatal "Not enough memory." on
failure; `mdl_aspect_radii(desc)`; for each LOD i with a model: if the model
is flagged compiled, `mdl_compile(model, verts[i], parents[i], flags[i])`; if
the colour offset is non-zero and the mode has 256 colours, copy the colour
bytes into the colour field (+03, the palette index byte only) of the
primitives (`mdl_apply_colors`; records are walked with the sizes above).
The file buffer is freed afterwards — only the generated code keeps the
geometry. Finally `mdl_time_of_day_colors`.

### 6.4 Vertex transform (generated code)

`mdl_compile` turns the vertex list into straight-line x86 code (one far
routine per LOD model, stored at M+06, buffer of up to 5000 bytes, retried
with 1000 bytes less on allocation failure, shrunk afterwards). A port can
implement the same arithmetic directly; to be bit exact it must reproduce the
digit decomposition and the table truncation described here.

**Transform tables** (built by `xf_build_tables` 74D8 whenever the camera or
object angles change, via `xf_tables_current` 790C): three tables
`T_X, T_Y, T_Z` (DS:5668/5728/57E8), 16 rows × 3 components × s32. Row 14 of
`T_a` = `M_cam × (M_obj × e_a)` where `e_a` is the unit vector 0x4000 on axis
a (M_obj skipped if the object's three angles are 0) computed with
`math_mat_vec_near` (so the high word is the 1.14 matrix element and the low
word holds 2 extra fraction bits). Rows 13..0 are
`hi(T[m]) = hi(T[14]) >> (14-m)` (arithmetic shifts; low words stay 0). The
row actually used for bit `b` of a coordinate is `b + K`, K = the object's
scale shift (render record +5, §8.3). The previous table set and its angles
are kept in far `5386:0000` (0x240 bytes) and swapped back in if the angles
match again.

**Signed digits** of a 16-bit offset v (`mdl_signed_digits`, A744, window
`W` = floor(log2(max |coordinate| of the model)), at most 14):
```
d[0..15] = 0; s = sign(v); v = |v|
for bit b = 0..15 with bit b of v set:
    if b <= W: d[b] = s  else: d[W] += s * (b - W + 1)   # only correct for b <= W+1
recode (A6C8): p = 0
while p < W:
    if d[p] == 0: p += 1; continue
    s = sign(d[p]); q = p
    repeat: if q >= W: break; q += 1; if d[q] == 0 or sign(d[q]) != s: break
    if q - p >= 3:
        d[p] -= 2*s; d[p+1 .. q-1] = 0; d[q] += s      # and examine p again
    else: p += 1
```
(A run s,s,s,…,s of length L>=3 followed by t becomes −s,0,…,0,t+s, which
has the same value.)

**Generated code per vertex i** (parent p, 16-bit arithmetic with wrap,
component c = x,y,z; `C` = camera-space object centre, §8.3):
```
base = (p == 0xFF) ? C.c : V[p].c      # "V[i-1]" is reused without a reload
dx,dy,dz = (p == 0xFF) ? v_i : v_i - v_p
V[i].c = base + sum over axes a, digits k of dx/dy/dz:  d_a[k] * hi(T_a[k+K].c)
```
The three components are produced by calling the same emitted routine three
times. Only the high words (+2, +6, +0A) of the 16-byte vertex slots are
written. With PNT flag bit 3 the same is done in 32 bits (low and high words,
base low words from DS:5B98 which are 0).

**Articulated parts**: vertices `0 .. first_part_first-1` form the body;
each part (BSP leaves with flag 4, collected in tree order) covers
`[first, last]`. Before a part whose angles are not all zero: save the object
matrix, build `M_part = math_rot_matrix(a0,a1,a2)`, if the object is rotated
`M = M_obj × M_part` else `M = M_part`, rebuild the tables; afterwards restore
the matrix and invalidate the tables. Each vertex of a part still uses its
parent (the pivot vertex usually belongs to the body).

The table-driven fallback `xf_transform_table` (7084/70EF: plain binary
digits of |x|,|y|,|z| with the sign applied at the end, 15 or 7 bits) is not
used by any game model.

## 7. World, objects and views

### 7.1 Object records and the arena

`world_begin` (01E7) creates everything for a mission:
`view_init(0x74A, world 0x7A4, persist 0, subsample 2, max 200, cache on,
max age 25, max rotation 16)` (fatal "Couldn't init coherence" on failure),
clears the world and allocates a 0x4C90-byte object arena in the far heap
(`obj_arena_init`); `g_obj_seg` (F450) = its segment. Object records live in
the arena and are referenced by 16-bit offsets in `g_obj_seg`.

`world_add_object(desc, x, z, flags)` (0234, cdecl, x/z are 32-bit *game*
units) builds on the stack
```
+00 u16 descriptor          +02 u16 flags          +04 u16 next (list link)
+06 s32 x = x << 8          +0A s32 y = desc+0x2C   +0E s32 z = z << 8
+12 s16 a0 (heading)        +14 s16 a1             +16 s16 a2      (all 0)
```
and copies it into the arena: 0x12 bytes if flag bit 1 (static, no angles)
is set, otherwise 0x18 bytes. With flag 0x4000 the record is appended to the
arena chain (later distributed into the grid = static scenery); otherwise it
is pushed at the front of the world's dynamic list (world+0x0C). Returns the
far pointer; `g_world_obj_count` is incremented. The caller may then modify
the record (position, angles, flags) at any time.

Object flags (+02) known to this segment:

| Bit | Meaning |
|---|---|
| 0x0001 | enabled (only enabled objects are drawn) |
| 0x0002 | static: record has no angles, drawn unrotated |
| 0x0004 | hidden while every frustum corner points upwards (g_sky_only) |
| 0x0008 | currently in a view's object list / draw list |
| 0x0010 | may use the projection cache (far, static scenery) |
| 0x0020 | group object (children at +18; no groups are built in this game) |
| 0x0040 | rejected by distance/world box last time: skip one test (flag cleared) |
| 0x0080 | partially clipped last time: next test skips the frustum test (clip flags forced to 0x0F), flag cleared |
| 0x0200 | never use precise mode |
| 0x4000 | (argument of world_add_object only) static grid object |

Group objects additionally use `+18 child list, +1A u8 cached visibility,
+1C u32 frame, +20 view, +22 parent group` (`r3d_group_visible` caches the
result per frame and view; the children are tested with the group as parent:
a fully visible group makes all children "inside", an invisible one hides
them). `obj_arena_append` would add to `g_arena_group` (CF18) children, but
CF18 is never set.

`world_end` (02B0): `obj_arena_close` terminates the chain and shrinks the
arena; `world_build_grid(world, chain, 24000, 24000)`; then 4FF8:000C.

### 7.2 World record and grid (DS:07A4)

```
+00 u8  ground colour   +01 u8 sky colour   +02 s16 horizon elevation term
+04 u16 grid width      +06 u16 grid height (cells)
+08 u16 offset of the cell array (in the grid segment)
+0A u16 object arena segment        +0C u16 dynamic object list head
+0E u16 grid segment
```
`world_build_grid(world, chain, ext_x, ext_z)` (A0A0): width =
`max(1, (ext_x + 0xFFFF) >> 16)` (ext in game units, so a cell is 65536 game
units = 2^24 world units); the game passes 24000, giving a **1 x 1 grid**.
A 500-byte far block holds the cell array (4 bytes per cell:
`+0 object list head`, `+2 near pointer to a 0-terminated list of cell
pointers`) and the per-cell lists. Each static object goes to cell
`(clamp(x>>24), clamp(z>>24))` (pushed at the list front, so the list order
is the reverse of creation order). Then, for every object, every other cell
whose Manhattan distance (in 256-game-unit steps, from the object to the
cell's square) is within the object's LOD-0 threshold gets a bit for the
object's cell; cells with identical bit sets share one list; the list of a
cell names the cells whose objects can be visible from it. Overflow of the
500 bytes is fatal. `world_cell_at(world, x, z)` (42C9) returns
`cells + 4*(w*clamp(z>>24) + clamp(x>>24))`. `world_free_grid` (A5EA) frees
the grid and the arena. `world_foreach(world, fn)` (421D) visits the dynamic
list and every cell list (recursing into groups).

### 7.3 View record (DS:074A, 0x5A bytes)

| Off | Meaning |
|---|---|
| +00 | world* |
| +02 | u32 frame counter (incremented after every render) |
| +06 | u16 subsample N (must be a power of two; 2) |
| +08 | u16 capacity of the object list (200) |
| +0A | u16 number of listed objects |
| +0C | far ptr object list, 6-byte entries `{obj, projection cache segment, parent group}` |
| +10 | u8 persistent mode (0 in the game) |
| +12..+1D | cache of `r3d_clip_shifts`: w, h, zoom, shift_x, shift_y, side_x, side_y |
| +1E..+31 | cache of `r3d_frustum_normals`: w, h, zoom, n_lr_x (+24), n_lr_z (+28), n_tb_y (+2C), n_tb_z (+30) (1.14) |
| +34..+45 | cache of `r3d_frustum_corners`: w, h, zoom, X (s32 +3A), Y (s32 +3E), Z (s32 +42) |
| +46..+4A | w, h and the cached horizon half length `max(w*20/23, h*23/20)` |
| +4C..+50 | zoom, world+02 and the cached horizon term `(world[+2]*30000) >> zoom` |
| +52 | buffer used only in 16-colour modes |
| +54 | projection cache: maximum age in frames (25) |
| +56 | projection cache: maximum camera rotation, angle units (16 = 2°) |
| +58 | u8 projection cache enabled (1) |

`view_free` frees the list, every cache segment and clears flag 8 of the
listed objects; `view_clear_list` empties the list; `view_mark`/`view_unmark`
set/clear flag 8 on the listed objects; `view_remark` is used with
`world_clear_cull_flags` (clears 0x40/0x80 on all objects).

`r3d_temp_add(view, obj)` (2E5C, cdecl) puts an object into one of 5 slots
(the first empty one, else slot 0) so that it is drawn in that view for the
next 8 frames even if the discovery scan has not found it yet.

## 8. Rendering a view — `r3d_render_view` (3090)

Signature (far pascal, source order):
`r3d_render_view(world*, s32 x, s32 y, s32 z, heading, pitch, roll,
viewport*, zoom, work_buf, work_size, view*, u8 unused, u8 wait)`.
The game calls it with `(0x7A4, cam.x, cam.y, cam.z, cam.heading,
cam.pitch, cam.roll, &cam.rect, cam.zoom, DS:D8BE, 5000, 0x74A, 0, 1)`
where the camera record is `{s32 x, y, z; s16 heading, pitch, roll; s16 rect[4]
(x,y,w,h); s16 zoom}`. Returns 0, 1 ("View Buffer Too Small") or 2 ("Object
List Too Small"); the caller treats 1 and 2 as fatal.

Work buffer: an array of render-record pointers grows upwards from
`work_buf`; 0x16-byte render records are allocated downwards from
`work_buf + work_size - 0x16`. When they would meet, status 1 is set and
gathering stops.

Render record (0x16 bytes, DS):
```
+00 LOD model          +02 next in the draw list
+04 u8 clip flags: 0 = inside; bit0 top plane, bit1 bottom, bit2 left, bit3 right; 0x0F forced
+05 u8 scale shift K   +06 s16 x, +08 s16 y, +0A s16 z: camera-space centre (see 8.3)
+0C u32 Manhattan distance |dx|+|dy|+|dz| to the camera (world units)
+10 projection cache segment   +12 parent group   +14 object
```

### 8.1 Frame set-up

1. Store the arguments in F430..F44F; `gfx_set_clip(rect)`; the projection
   centre is the clip centre `(cx, cy)`. (Model radii were made
   aspect-correct at load time by `mdl_aspect_radii`: `+04 = g_aspect_x ?
   hi(r * 0x12666) : r`, `+06 = g_aspect_y ? hi(r * 0xDEAA) : r`, i.e. in the
   game `+04 = r`, `+06 = r*20/23`; the game calls `r3d_set_aspect(20, 23)`
   so `g_aspect_y` = 1.)
2. `r3d_gen_projection(zoom)` (§9.1).
3. `r3d_frustum_normals` (4D9C, cached per view on w,h,zoom):
   `f = 1 << zoom`; horizontal `a = clip_w >> 1`: `len = sqrt(a² + f²)`
   (16.16, `math_sqrt_long`), `n_lr_x = fdiv(f, len) >> 2`,
   `n_lr_z = fdiv(a, len) >> 2` (1.14); vertical the same with
   `clip_h >> 1` → `n_tb_y`, `n_tb_z`.
4. `r3d_camera_matrix` (56C4, cached on the three angles): build
   `A = r3d_view_matrices` and the pitch/roll-only matrix `B`:
   ```
   hc,hs = cos,sin(-heading); pc,ps = cos,sin(-pitch); rc,rs = cos,sin(-roll)   (1.14)
   m(u,v) = (u*v) >> 14 (16-bit result)
   t1 = m(ps,rc); t2 = m(ps,rs)
   A = [[ m'(t2,hs)+m'(hc,rc) ,  m(pc,rs) , m'(t2,hc)-m'(hs,rc) ],
        [ m'(t1,hs)-m'(hc,rs) ,  m(pc,rc) , m'(t1,hc)+m'(hs,rs) ],
        [ m(hs,pc)            ,  -ps      , m(hc,pc)            ]]
        where m'(a,b)+m'(c,d) = (a*b + c*d) >> 14 computed on the 32-bit sum
   B = [[ rc , m(pc,rs) , t2 ], [ -rs , m(pc,rc) , t1 ], [ 0 , -ps , pc ]]
   ```
   `A` → F452 (camera matrix), its transpose → F484 (camera to world), B →
   F464. Then the pixel aspect correction: with the game's 23:20 setting
   (`g_aspect_y`) the **y rows** of F452 and F464 are scaled:
   `e' = (((e>>1) * f) << 2) >> 16` with `f = (0xDEAA >> 1) = 0x6F55`
   (≈ 20/23). (With `g_aspect_x` the x rows would be scaled by 23/20.)
   Camera space: `v_cam = F452 × (v_world - cam)`.
5. `r3d_frustum_corners` (5838): `X = w << (9-zoom)`, `Y = h << (9-zoom)`
   (right shift if zoom > 9) as the high words of 32-bit values, `Z = 0x400`
   (high word); with `g_aspect_y` `Y = fmul(Y, 23/20)`. The corners
   `(-X,+Y,Z) (+X,+Y,Z) (-X,-Y,Z) (+X,-Y,Z)` are rotated to world space
   with F484. `g_sky_only` = all four corner y high words > 10. Then the
   world boxes (8.3) are updated.
6. `r3d_clip_shifts` (2F40, cached): slope `r = (w/2) / 2^zoom` as 16.16;
   `r3d_pow2_ratio(r)`: if `r < 1`: side = 1 ("shift z"), shift =
   `floor(log2(1/r))` (16 if r = 0) — computed as the number of doublings to
   reach >= 1, minus 1 when r is not an exact power of two; else side = 0
   ("shift x,y"), shift = `ceil(log2(r))` (0..14). The same for `(h/2)/2^zoom`.
   The clip planes used in 3D are therefore `|x| <= z·2^shift` resp.
   `|y| <= z·2^shift`, i.e. the frustum widened to the next power of two;
   the 2D clip box does the rest.

### 8.2 Gathering objects

```
cell = world_cell_at(world, cam.x, cam.z); N = view.subsample; skip = (N-1) & frame
if view.persist: view_mark(view)
batch(r3d_gather_list(cell.list, skip, N, parent 0))
for k = skip, skip+N, skip+2N, ... while cell.visible_cells[k] != 0 and status == 0:
    batch(r3d_gather_list(cell.visible_cells[k].list, 0, 1, 0))
if status == 0: batch(r3d_gather_list(world.dynamic_list, skip, N, 0))
# persistent list, g_in_view_list = 1 (no world-box test)
for each entry e of view.list (count view+0A):
    if status == 0: rec = new; rec.parent = e.parent; rec.obj = e.obj
        if r3d_obj_visible(e.obj, rec): rec.cache = e.cache; append rec
            (status = 1 if the buffer is full)
        else goto drop
    else drop: clear e.obj flag 8; free e.cache (if any)
merge the batch, sorting it first only when the frame counter is odd
for each of the 5 temporary slots with obj != 0 and view == this view:
    if !(obj.flags & 1) or (obj.flags & 8) or frames_left-- == 0: clear slot
    else rec = new {parent 0, obj}; if visible: obj.flags |= 8, cache 0, append
batch(...)
```
`batch(...)` = if records were added: `r3d_sort_batch` (skipped when already
in order) then `r3d_merge_draw_list`.

`r3d_gather_list(list, skip, stride, parent)` (55A8): skip `skip` objects,
then test every `stride`-th object. Objects with flag 8 are skipped. For a
normal object: allocate a record `{parent, obj}`; if `r3d_obj_visible`:
`flags |= 8`, `rec.cache = 0`, append. For a group object: store the
visibility (0xFF if invisible, else the record's clip flags), the frame and
the view in the group and, if visible, gather its children with stride 1 and
the group as parent (the group itself is not drawn).

So new objects are found by a scan that covers only 1/N of the camera cell's
and dynamic lists per frame; objects that were visible stay in the view list
(max 200) and are re-tested every frame.

### 8.3 Visibility of one object — `r3d_obj_visible(obj, rec)` (53BB)

```
if !(flags & 1): return 0
if flags & 0x40: flags &= ~0x40; return 0
if g_sky_only and (flags & 4): return 0
desc = obj.desc
d = |x-cam.x| + |y-cam.y| + |z-cam.z|   (32-bit) ; rec.dist = d
D = (d >> 16) + 1
lod = 2 - (t0 < D) - (t1 < D) - (t2 < D)      (unsigned compares, t = desc+0E..)
if desc.callback: lod = callback(obj, lod)
if lod < 0: goto far
if !g_in_view_list and !r3d_cull_world_box(obj, desc): goto far
r3d_obj_to_camera(obj, rec)                          (below)
if rec.parent: v = r3d_group_visible(parent)
    v == 0: rec.clip = 0; goto accept
    v == 0xFF: return 0
if flags & 0x80: flags &= ~0x80; rec.clip = 0x0F; goto accept
if !r3d_cull_sphere(rec, obj): return 0
if rec.clip != 0 and !view.persist: flags |= 0x80
accept: rec.model = desc.lod[lod]; return 1
far: g_stat_far++; if !view.persist: flags |= 0x40; return 0
```
Note the time-slicing: a rejected object skips its next test; a partially
clipped object is accepted without test (and fully clipped) on the next frame.
With the single LOD of every game model, index 0 is used when
`D <= t0` (t1 = t2 = 0 always count as exceeded).

**World box cull** (`r3d_cull_world_box` 82AC): size class
`c = desc+1A` (`>= 20` → always passes, `< 10` → 10), `r = desc+08`;
passes if `x + r >= XMIN[c]`, `x - r <= XMAX[c]`, `z + r >= ZMIN[c]`,
`z - r <= ZMAX[c]` (signed 32-bit). The tables (F4F2, F544, F596, F5E8,
index `c-10`) are built by `r3d_build_world_boxes` (8332): for each of x and
z, `lo = min(0, corner components)` and `hi = max(0, corner components)`
over the four world-space corner directions, each value taken as its bits
8..23 (`>> 8`, 16 significant bits), then `TABLE[c] = cam + (value << (c - 10))`
for c = 10..19 (32-bit; the corner directions have depth 2^26, so class c
covers the view pyramid up to depth `2^(c+8)` world units).
`r3d_update_world_boxes` (8599) rebuilds them when 20 calls have passed, any
camera angle changed by >= 120 units (15°), or the viewport/zoom changed;
otherwise it only translates them: if the camera x moved by `|Δx| >= 0x6600`
world units since the position the tables were last built/translated for,
all x tables are shifted by Δx and that position updated; the same for z.
Smaller movements are ignored (the boxes lag behind by up to 0x65FF).

**Camera transform** (`r3d_obj_to_camera` 506B):
```
s = desc+0C (signed)
for c in x,y,z: r_c = obj.c - cam.c (32-bit); r_c = (s>0) ? r_c >> s : r_c << -s; r_c <<= 8
m = (|hi(r_x)| | |hi(r_y)| | |hi(r_z)|) + desc.radius + 1        (model units)
K = 0 if m >= 0x2000, 1 if >= 0x1000, ..., 12 if >= 2, else 13 ; rec.K = K
r_c <<= K (32-bit) ; C = F452 × (hi(r_x), hi(r_y), hi(r_z))  (math_mat_vec_near)
rec.x,y,z = hi(C)
```
All camera-space quantities of this object (centre, vertices) are therefore in
units of `2^(8+s-K)` world units; K keeps the object within 14 bits.

**Sphere/frustum test** (`r3d_cull_sphere` 4E9C): with `rx = desc+04`,
`ry = desc+06`, `r = desc+02`:
```
if (z >> K) + r < 0: return 0 (behind)           (arithmetic shift)
P1 = x*n_lr_x ; P2 = y*n_tb_y ; P3 = z*n_lr_z ; P4 = z*n_tb_z     (32-bit)
each shifted by (K-2): right shift if K >= 2, else left by 2-K; take the high words h1..h4
L = h3 + h1 (left plane),  Rt = h3 - h1 (right),  Bt = h4 + h2 (bottom),  T = h4 - h2 (top)
if T < -ry or Bt < -ry or L < -rx or Rt < -rx: return 0 (outside)
if all of T,Bt > ry and L,Rt > rx: rec.clip = 0 (inside)
else rec.clip = (T <= ry) | (Bt <= ry)<<1 | (L <= rx)<<2 | (Rt <= rx)<<3
```

### 8.4 Draw order

`r3d_draw_order_cmp(p, q)` (5553, source order): with `lp`, `lq` = layer
byte (+00) of the objects' descriptors: `lp < lq → -1`, `lp > lq → +1`;
equal layers `< 0x80` → 0; otherwise by distance: `p.dist > q.dist → -1`
(farther first), equal → 0, `p.dist < q.dist → +1`. Negative = p is drawn
before q. The draw list is therefore ordered by increasing layer and, within
layers >= 0x80, from far to near.

`r3d_sort_batch(arr, n)` (ADFA): nothing is done if
`cmp(arr[i], arr[i+1]) <= 0` for every i; otherwise
`r3d_quicksort(&arr[0], &arr[n-1])` (AE48):
```
qs(lo, hi):                                  # pointers, inclusive
  while lo < hi:
    i = lo; j = hi + 1
    loop:
      i += 1; while i < hi and cmp(*i, *lo) <= 0: i += 1      # stops at hi without comparing it
      j -= 1; while j > lo and cmp(*j, *lo) >= 0: j -= 1
      if i < j: swap(*i, *j); continue loop
      break
    swap(*lo, *j)
    if (hi - j) <= (j - lo): qs(j+1, hi); hi = j-1
    else:                    qs(lo, j-1); lo = j+1
```

`r3d_merge_draw_list(arr, n, head)` (2E96): if the list is empty the array
is linked in order. Otherwise for each new record e (array order), starting
at the position after the previously inserted record: advance over list
elements a while `cmp(e, a) > 0`, then insert e before a (at the end if the
list is exhausted). Records of the same unsorted layer therefore end up in
front of older ones.

### 8.5 Sky and ground — `r3d_draw_sky_ground(ground, sky)` (671C)

Called with `world+00` (ground) and `world+01` (sky) before the objects; if
`g_rv_wait` the frame limiter wait (4A1C:0192) is done first.

```
if ground == sky: if ground != 0xFF: fill_rows(clip_y0, clip_h, ground); return
H = view cache of (world[+2] * 30000) >> zoom            (32-bit product, low word)
P = (x=0, y=H, z=30000) as 32-bit (high words); P = F464 × P
(sx, sy) = precise projection of P (9.2)
if |sx| < 15001 and |sy| < 15001:
    L = max(w*20/23, h*23/20)      (high words of 32-bit products, cached)
    C = (sx, sy); A = (sx-L, sy); B = (sx+L, sy)
    A = math_rotate_2d(A, C, -roll); B = math_rotate_2d(B, C, -roll)
    A.x = C.x + hi((A.x-C.x) * 0x12666); B.x likewise     (x offsets * 23/20)

        clamp ymin >= clip_y0, ymax <= clip_y1; if ymax < ymin: ymin = ymax
        band_left  = (A.y < B.y) ? ground : sky ; other = the opposite
        above      = (B.x < A.x) ? ground : sky ; below = the opposite

```
`r3d_horizon_rows(tab, ymax*, ymin*, B, C)` (601D): if `B.y < C.y` reflect
B through C; `Δ = B.y - C.y`; rows `C.y-Δ .. C.y+Δ`. Step per row (8.8):
`Δ == 1 → (B.x-C.x) << 8`, else `((B.x-C.x) << 9 + Δ) / (2Δ)` (overflow →
±0x7FFF). Accumulator (24-bit) starts at `C.x*256 + 127`; for k = 0..Δ:
`x = acc >> 8`; `tab[C.y+k] = x`, `tab[C.y-k] = 2*C.x - x` (only rows inside
the clip are stored); `acc += step`.

### 8.6 Drawing one object — `r3d_draw_object(obj, rec)` (B37E)

```

angles = (flags & 2) ? (0,0,0) : obj.a0,a1,a2
desc = obj.desc   (swap-in if desc+26 != 0)
g_precise = desc.radius_long_hi (desc+0A) > 7 and rec.dist <= desc.radius_long
            and !(flags & 0x200)

C = rec.x,y,z ; K = rec.K ; cache = rec.cache
if cache and rec.clip == 0 and cache is valid (below): r3d_cache_draw; return

   and hi(rec.dist) > 4*desc+0A + 11:  allocate a cache if none
   ((np+1)*2 + 0x1E + nv*4 bytes; +14 = far ptr to the primitive list at +1E,
    +10 = far ptr to the vertex offsets after it)
else: free the cache
reset the facing caches of the leading type-0 records (mdl_reset_facing)
if angles != 0 and != the angles of the current object matrix:
    F62C = math_rot_matrix(a0, a1, a2)
transform: call model+06 (generated code) (or xf_transform_table)

if cache: record the drawn primitive pointers into the cache list

```
Cache validity (all must hold): `frame - cache.frame <= view+54`,
`|heading - cache.h|`, `|pitch - cache.p|`, `|roll - cache.r| < view+56`,
the object is outside its bounding radius, `cache.desc == desc`,
`cache.model == model`, `cache.zoom == zoom`, `cache.aspect == 54E4/54E6`.
Cache header: `+00 u32 frame, +04/+06/+08 camera angles, +0A zoom,
+0C/+0E aspect, +10 far ptr vertex offsets, +14 far ptr primitive list,
+18 desc, +1A model, +1C K`. `r3d_cache_store` projects the object origin
`C` (9.1) and stores for every vertex `(sx - Cx, sy - Cy)`;
`r3d_cache_draw` projects the new origin and restores every vertex's screen
position as offset + new origin, then calls the draw routine of every listed
primitive (no clipping, no facing tests: the list already contains only the
primitives that were visible). Far static objects therefore move with the
camera translation but keep their projected shape for up to 25 frames while
the camera rotates less than 2°.

**BSP walk** (`r3d_draw_bsp` 824B): internal node: if
`r3d_prim_visible(node)` draw child B then child A, else A then B. Leaf with
list: for each primitive, if `r3d_prim_visible(prim)` call
`g_prim_draw_tbl[type]`.

**Facing** (`r3d_prim_visible` 78E8 / `r3d_face_side` 959A): mode = type &
0x18: 0 → visible; 8 → hidden; else take the facing record F = [prim+1]; if
`F+05 == 0` compute it: with vertices P0,P1,P2 = F+07,+08,+09 (camera-space
16-bit high words) `e1 = P0-P1`, `e2 = P2-P1`,
`n = (e1.y*e2.z - e1.z*e2.y, e1.z*e2.x - e1.x*e2.z, e1.x*e2.y - e1.y*e2.x)`
(32-bit; if any 16-bit difference overflows all coordinates are halved
first); then every component is shifted right by 4 until all three fit in 16
bits, then by 1 more; `dot = n·P1` (32-bit sum of 16x16 products);
`F+05 = dot < 0 ? 0x18 : 0x10`. The primitive is visible if `F+05 == mode`.

### 8.7 Primitives

Vertex slots: 16 bytes at DS:CF8A + 16·i: `s32 x, y, z` (only the high words
are written by the normal generated code), `+0C sx` (0x7FFE = not yet
projected), `+0E sy`. Each routine projects a vertex at most once per object.

* **Type 0 polygon** (86F8): n vertex slots.
  1. If `g_draw_clip == 0`: project every vertex (cached) and fill.
  2. Otherwise apply the vertical plane shift (`shift_y`: z if `side_y`, else
     x and y) and test every vertex for `|y| <= z`; if all pass the polygon
     is projected without clipping as in 1.
  3. Else copy the vertices into the clip ring (DS:5926, 16 bytes: s32 x,y,z
     with the vertical shift applied, `+0C` source slot, `+0E` new flag = 0).
     Clip bits 0/1: only bit 0 → `clip_poly_top` (plane `y <= z`); only bit 1
     → `clip_poly_bottom` (`y >= -z`); both → top then bottom, or bottom then
     top when the high word of ring[0].y or the word at ring+0x12 (ring[1].x
     high word — probably meant to be ring[1].y) is negative.
  4. Undo the vertical shift: new vertices are shifted back, original ones are
     re-copied from their slot.
  5. If every ring vertex has `z >= 2^24`, or `z > 0` with
     `hi(z) >= |x >> 24|` and `hi(z) >= |y >> 24|` (signed byte magnitudes),
     skip to 7 (no horizontal clipping needed). Otherwise apply the horizontal shift
     (`shift_x`/`side_x`), clip with `clip_poly_left` (`x >= -z`) if clip bit 2
     is set and **again with `clip_poly_left`** if bit 3 is set (the right
     plane routine is never called — original bug; the 2D clip box handles the
     right side), and undo the shift.
  6. After any clip step a count <= 0 draws nothing.
  7. Project: original vertices use (and fill) their slot's cached
     projection, new vertices are projected directly; then
     `gfx_fill_polygon(points, count, colour word)`.
* **Type 1 line** (8CB9): unclipped → project both ends (cached). Clipped →
  `clip_line_frustum` (59BC; the bisection variant 75B6 in precise mode),
  which only considers the **top and bottom** planes: with the vertical shift
  applied, up to 8 iterations compute outcodes (`z < y`, `y < -z` per
  endpoint), return −1 if both endpoints are outside the same plane, stop when
  both are inside, otherwise move one outside endpoint onto the plane
  (`t = (d0 << 12) / (d0 - d1)` with d = signed plane distance, x and y
  interpolated with 12 fractional bits and rounding, z set to ±y). Result bit
  0/1 = endpoint 0/1 replaced (its projection is not cached). Then
  `gfx_line(x0, y0, x1, y1, colour)`.
* **Type 2 point** (8E08): drawn if `z >= 0` and (`hi(z) > 0` or
  `lo(z) < 0x8000`): `gfx_pixel(sx, sy, colour)`.
* **Type 3 disc** (8E67): drawn if `z > 0`; radius `ρ = r << K`; project
  `(ρ, 0, z)` (x high word ρ, y 0, z the vertex's z) → `rp = sx' - cx`;
  `gfx_fill_circle(sx, sy, rp, colour)`.
* **Type 4 callback** (8EF6): drawn if `z > 0`: far call `routine(prim,
  sx, sy)` (cdecl) — used for sprites attached to 3D points.

**Polygon clipping** (`clip_poly_*`, 9C14/9D2E/9E5D/9F89): Sutherland–Hodgman
over the ring of `m` 16-byte clip vertices in place; an inside test uses the
32-bit values (e.g. top: inside if `y <= z`). For each vertex (starting with
the edge from the last vertex): inside→inside keeps the vertex;
inside→outside emits the intersection; outside→inside emits the intersection
then the vertex; outside→outside emits nothing. Returns the new count.
Intersections (`clip_*_div`, 7954/7B59/7D60): with the rounded high words
(`hi + (lo < 0 ? 1 : 0)`) of both endpoints, e.g. top plane:
`t = ((z1-y1) << 12) / ((z1-y1) - (z2-y2))` (32/32, operands shifted right
together until the divisor fits 15 bits, retried with a halved numerator on
divide overflow), then `x = x1 + (t*(x2-x1) >> 12)` (32-bit fixed point with
the low 16 bits kept), `y = z = y1 + t*(y2-y1) >> 12`; flag "new" = 1. If
the divisor is 0 one endpoint is copied instead. For the top (bottom) plane,
if both endpoints lie exactly on the opposite plane `y = -z` (`y = z`) the
result's y and z are forced to 0. The precise-mode callbacks (3814/38C6/3978) instead
bisect the segment 32 times (`clip_*_bisect`, midpoint = average of the
32-bit coordinates with overflow-safe halving) until the midpoint is on the
plane, and zero x,y,z if both endpoints were at the origin.

## 9. Projection

### 9.1 Normal projection (generated code at 2255:6D0A)

`r3d_gen_projection` (6EC6) regenerates the routine whenever the zoom
changes. Input AX = vertex record (x,y,z as s32; only the high words are
used), output AX = sx, CX = sy:

```
if g_precise: return r3d_project_precise(v)                       (9.2)
q = shiftz(sext32(y_hi)) / z_hi        (IDIV, truncation toward zero)
sy = cy - q          ; signed overflow of the subtraction → sy = 0x7F00
q = shiftz(sext32(x_hi)) / z_hi
sx = cx + q          ; signed overflow → sx = 0x7F00
```
`shiftz(D)` is the emitted shift sequence for `zoom`:
* zoom < 6: `D << zoom` (zoom times `shl ax,1 / rcl dx,1`);
* 6 <= zoom < 8: `D' = (D << 8) | (D & 0xFF)` (the low byte is *not*
  cleared: `mov dh,dl / mov dl,ah / mov ah,al`), then `D' >> (8-zoom)`
  (arithmetic);
* zoom >= 8: `D'` as above, then `D' << (zoom-8)`.
(zoom 0 is not supported.) `cx`/`cy` are the clip centre.

Divide overflow (quotient out of 16-bit range, or `z_hi == 0`) is handled by
the INT 0 handler (6B74) through the CS-resident fix-up addresses 6B70/6B72:
* y division: `q = 0x7F00`, negated if the signs of `y_hi` and `z_hi` differ;
  continue with `sy = cy - q` (overflow → 0x7F00);
* x division with `z_hi != 0`: `q = ±0x7F00` by the signs of `x_hi`, `z_hi`,
  continue with `sx = cx + q`;
* x division with `z_hi == 0`: the routine returns immediately with
  `sx = x_hi > 0 ? 10000 : x_hi == 0 ? cx : -10000` and
  `sy = y_hi > 0 ? 10000 : y_hi == 0 ? cy : -10000` (note the y sign is
  inverted compared with the normal case).

Whenever a divide overflow happens anywhere, `g_div_overflow` = 0xFF.

`r3d_project(v, &sx, &sy)` (4328, pascal) is the far entry used by other
segments; `r3d_project_to` (6CF3) the near one.

### 9.2 Precise projection (7047)

Used when `g_precise` (large object with the camera inside its bounding
radius) and for the horizon point. With full 32-bit coordinates:
`sx = cx + div(x, z)` (0x7F00 on overflow), `sy = cy - div(y, z)`
(0x7F00 on overflow), where `div(n, d)` (6F24) is:
```
if d == 0: return n > 0 ? 0x7F00 : n < 0 ? -0x7F00 : 0        (n > 0 includes hi==0, lo!=0)
neg = sign(n) != sign(d); n = |n|; d = |d|
N = n << zoom as a 48-bit value (top word T = bits 32..47); e = 0
while T >= hi(d):  if hi(d) < 0x4000: d <<= 1  else: N >>= 1 (arithmetic), e += 1
while T < 0x4000 and hi(d) < 0x4000: N <<= 1; d <<= 1
q = (bits 16..47 of N) / hi(d)            (32/16 signed division; lo(d) is ignored)
repeat e times: q <<= 1; if the sign changes: q = 0x7F00; stop
return neg ? -q : q
```

## 10. Porting notes

* The whole 3D pipeline depends only on data inside the executable (model
  descriptors, LOD models, primitive records and BSP trees in DGROUP; sine,
  atan and RNG tables in far segments 5327, 52E7, 5382) plus the `.pnt`
  files; a port should read them from the user's `st.exe` (file offsets:
  DGROUP 0x4A8E0 + offset; far segment S → 0x3CF0 + (S−0x1000)·16).
* Integer arithmetic matters for matching the original frame exactly:
  16-bit wrap-around in the vertex code, truncating divisions, the
  signed-digit decomposition, the halving tables, the aspect-scaled matrix
  and the projection quirks above.
* Low words of vertex slots are only written by 32-bit (PNT flag 8) models;
  other models leave whatever an earlier 32-bit model stored (the slots are
  zero at start). They matter only in precise mode and for the `z_hi == 0`
  cases of point primitives.
* Everything drawn goes through the 320x200 page with the clip box; the
  row cache, latched copies and VGA register handling can be dropped.
